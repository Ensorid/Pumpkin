# Initialize a Pumpkin plugin (Rust + WASM)

## 1. What the server expects

- A `.wasm` file in **component model** format placed in `./plugins/` (next to the server executable). The folder is created if it does not exist, and the server watches `.wasm` file changes for hot reload.
- The server detects the API version (`v0.1` or `v0.2`) from the component. The current `pumpkin-plugin-api` crate generates its bindings against **v0.1**. The v0.2 host is disabled by default (the `plugin-v0_2` feature of the `pumpkin` binary).
- The plugin exports `init-plugin` (generated by `register_plugin!`), then the server calls `metadata`, then `on-load`.

## 2. Create the project

```bash
cargo new --lib my-plugin
cd my-plugin
rustup target add wasm32-wasip2
```

`Cargo.toml`:

```toml
[package]
name = "my-plugin"
version = "0.1.0"
edition = "2024"

[lib]
crate-type = ["cdylib"]

[dependencies]
pumpkin-plugin-api = { git = "https://github.com/Pumpkin-MC/Pumpkin" }
tracing = "0.1"
```

Notes:
- `crate-type = ["cdylib"]` is required to produce a WASM module.
- To test against the fork, replace the URL with `https://github.com/Ensorid/Pumpkin` (add `branch = "..."` if needed), or use `path = "../pumpkin/crates/pumpkin-plugin-api"` locally.
- `tracing` is used for logging: `register_plugin` installs a subscriber that forwards logs to the server.

## 3. Minimal code (`src/lib.rs`)

```rust
use pumpkin_plugin_api::{
    Context, Plugin, PluginMetadata, Result, register_plugin,
};

struct MyPlugin;

impl Plugin for MyPlugin {
    // Called once, before on_load.
    fn new() -> Self {
        MyPlugin
    }

    fn metadata(&self) -> PluginMetadata {
        PluginMetadata {
            name: "my-plugin".into(),
            version: "0.1.0".into(),
            authors: vec!["your-name".into()],
            description: "My first Pumpkin plugin.".into(),
            dependencies: vec![],
            // Permissions requested from the host (see `pumpkin_plugin_api::permissions`).
            permissions: vec![],
        }
    }

    // Register commands, events, permissions, etc. here.
    fn on_load(&self, _context: Context) -> Result<()> {
        tracing::info!("my-plugin loaded");
        Ok(())
    }

    fn on_unload(&self, _context: Context) -> Result<()> {
        tracing::info!("my-plugin unloaded");
        Ok(())
    }
}

register_plugin!(MyPlugin);
```

Key points of the `Plugin` trait:
- The trait requires `Send + Sync` and its methods take `&self`: any mutable state goes through thread-safe interior mutability (`Mutex`, atomics, ...).
- Do not hold a non-reentrant lock across a host call: the call can re-trigger an event or IPC message in the same plugin before it returns.
- `register_plugin!` must be called only once.

## 4. Permissions

`metadata().permissions` lists the requested accesses as strings. The constants are in `pumpkin_plugin_api::permissions`:

- network: `NETWORK_DNS`, `NETWORK_TCP`, `NETWORK_OUTBOUND`, `HTTP_OUTBOUND`, ...
- files in the plugin's data folder: `FS_READ_DATA`, `FS_WRITE_DATA` (folder `plugins/data/<name>`)
- system: `SYS_ENV`, `SYS_INFO`, ...

Without a permission, the matching feature is not accessible. Request only what is needed.

For persistence there is no dedicated storage API: the plugin reads and writes its own files with `std::fs`, under the path returned by `context.get_data_folder()` (call it in `on_load` or `on_unload`).

## 5. Build and install

```bash
cargo build --release --target wasm32-wasip2
cp target/wasm32-wasip2/release/my_plugin.wasm <server-folder>/plugins/
```

The output file name uses underscores (`my_plugin.wasm`). At startup (or when the file is copied, if hot reload is active), the server loads the plugin and logs its name and version.

## To verify

- **Build command**: the repository does not document the exact command. The `wasm32-wasip2` target directly produces a component, but the API uses `cargo-component` metadata (`[package.metadata.component]`) and the loader recognizes `cargo-component` among known tools. If the server rejects the file ("ComponentNewFailed" or "ApiMismatch"), try `cargo component build --release`.
- **Dependency form**: `pumpkin-plugin-api` is a workspace member of the repository and is not confirmed to be published on crates.io. Adapt `git`/`path` to the source you use.
- **Hot reload default**: the code watches `./plugins`, but the default value of the `hot_reload_enabled` flag was not checked.
- **Doc example**: the comment in `lib.rs` shows `on_load(&self, context: &Context)`, while the trait declares `on_load(&self, context: Context)`. Follow the trait signature.
